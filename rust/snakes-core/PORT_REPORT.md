# Snakes mechanics core

Implemented only under `rust/snakes-core/`. No commits, branches, review loops,
servers or watchers. Source reference: repository revision
`5f4f1d9a07ac6292a668868aaf797af68f105802`, `qml/visuals/Snakes.qml`.
The generated golden fixture records the source SHA-256 and is regenerated by
extracting the actual unchanged JS mechanics functions into Node, replacing
only the AI/safety hooks with scripted inputs. No JS implementation was copied
into production Rust. Zero dependencies; toolchain `/usr/bin/cargo` and
`/usr/bin/rustc` 1.93.1; all Cargo invocations frozen, without network/rustup.

## Files and layout

- `Cargo.toml`, `Cargo.lock`, `.gitignore`: fixed package/staticlib contract,
  specified release/dev profiles and ignored build artifacts.
- `src/lib.rs`: public Rust API and module exports.
- `src/rng.rs`: exact unsigned LCG with JS f64 seed derivation, including large
  signed seeds whose initial multiplication loses low integer bits.
- `src/math.rs`: f64 geometry, single-axis toroidal deltas, point/segment and
  swept segment distances, intersection/touching checks, angle normalization.
- `src/world.rs`: validated config, private POD snake/food state, flat segment
  arrays, trail rings, reusable linked collision buckets, complete tick phases.
- `src/controller.rs`: controller trait, function-based scripted controller,
  borrowed recorded-tick table and explicitly temporary nearest-food/wall
  baseline controller. Controllers cannot consume the world RNG.
- `src/ffi.rs`, `include/snakes_core.h`: C ABI v1 and matching layout assertions.
- `src/world/tests.rs`: ported mechanics scenarios and private cap fixtures.
- `src/world/golden.rs`, `tests/generate_js_golden.py`: JS parity/RNG fixtures.
- `tests/allocation.rs`: standalone counting-global-allocator binary, compiling
  the same private mechanics modules directly so cap setup needs no production
  mutation API. This also executes the mechanics tests a second time.
- `tests/controllers.rs`, `tests/ffi.rs`: recorded controls and Rust FFI tests.
- `tests/ffi_smoke.c`: actual C client of the release static library.
- `examples/bench_mechanics.rs`: eight-minute benchmark, per-minute and overall
  average/percentiles, populations and deaths.

Storage is allocated during creation/reconfiguration/resize, never a tick.
Segments occupy fixed strides of 1600 for at most 14 slots. Active records are
exported compactly. Food retains order when removed, matching JS splice order.
Each snake has a flat preallocated power-of-two trail ring; capacity derives
from the maximum possible body length/radius and minimum 30 Hz step distance,
with space for birth samples and pruning slack. Resize/capacity changes preserve
retained trail samples rather than rebuilding a curved path. Grid buckets use
flat head/next arrays and preserve JS occupant ordering. This favors steady
CPU cost over memory: the 3440x1440/scale100 world reserves about 21 MiB for
trails (14 * 65536 * 24 bytes), plus segments/grid/state. Reconfiguration may
allocate. Geometry limits bound those up-front allocations.

IDs are slot indices, with generation counters incremented on every birth,
including world restarts. Counters survive density shrink/grow. Growth inserts
behind the head, moving old segments and their previous positions together;
the new segment's previous position is the new head position, exactly as JS.
Dead slots export zero segments.

## Tick and configuration behavior

Exactly 1/30 second: advance simulation time, update/expire/drift/replenish
food, compute growth slots, ask every live snake's controller against the same
pre-movement world, move or respawn slots in order, vacuum/feed, mark wall/head/
body/self collisions, explode dying snakes in order, increment tick. New births
are fed/collision-tested that tick but do not move until the next tick.

Density maps to 3–14 snakes, trails to 28–190 ambient food (183 at trails100),
and death bursts to at most ambient+260 (450 at the ambient limit). Radius,
area budgets, growth costs/stretch/thickening, speed penalty/boost/rush,
intelligence-limited turn rate and maturity-dependent curvature match JS.
Birth RNG consumes radius, length, initial best-spawn angle, each attempted
spawn's x/y/angle, then speed bias, turn bias, wander phase, aggression and
initial brain cooldown, in source order. There is no per-snake randomized
intelligence-bias field in the source; global intelligence affects mechanics.
The original unused traits and cooldown draw are retained for future AI.

Count or seed changes restart the simulation; other reconfiguration preserves
state. Geometry rescales current/previous positions, unwrapped trail samples,
food positions/velocities/attraction targets. Existing snake radii and food
sizes remain unchanged on resize, as in JS. Growth budgets are recomputed.

## ABI summary

Every exported symbol starts with `snakes_core_`:
`abi_version`, `create`, `destroy`, `reconfigure`, `resize`, `set_steering`,
`step`, `get_frame_sizes`, `export_frame`, `stats`.

Opaque handle; C records have explicit integer widths, `repr(C)` Rust layout,
matching C/C++ static assertions and record-count capacities (`size_t`). Config
uses f64 inputs and 0/1 flags. Export includes all snake slots (ID/generation/
alive/radius/angle/desired/color and compact segment offset/count), f32 current/
previous segment pairs, food ID/position/size/phase/vacuum attraction/target/
color, and frame tick/time/world size/geometry generation. Stats include live
snakes, live segments, food and total/wall/head/body/self deaths. Return codes:
0 OK, 1 invalid argument, 2 insufficient buffer. Capacity failure changes no
output. No Rust allocation or buffer ownership crosses the ABI.

Steering inputs replace a persistent per-slot table atomically. Generation 0
matches any generation; stale specific generations are ignored. Omitted slots
continue straight; length 0 selects the temporary baseline. For recorded
playback, replace inputs before each `step(world,1)`. Rush is a fractional
boost [0,1]. Angles are finite radians. Handle calls must be serialized; caller
pointers must refer to aligned, valid, disjoint live memory. Nulls, malformed
config/numeric values/flags, invalid/duplicate IDs, excessive input lengths,
excessive tick counts and insufficient capacities are checked. As usual for
an unsafe C ABI, arbitrary dangling pointers/double destruction cannot be
validated. No panic arises from validated numeric/length inputs.

## Intentional changes and limits

- AI target choice/planning/collision and wall safety/food reservations/cluster
  analysis are omitted. The baseline is intentionally weak; there is no claim
  of population parity against the original AI. Food vacuum ownership remains
  mechanics and is fully retained. Corpse feast/trail metadata is retained for
  future controllers. No mechanics RNG draws were removed or added.
- Fixed 30 Hz native mechanics; the QML 60 Hz Canvas compatibility/presentation
  accumulator, rendering offsets/copies/visuals and frame-driver timing are
  outside this crate. JSON snapshot/restore and developer paths are not ported.
  `wrappingOffsets` is renderer-only; `segmentMotion` is used by AI prediction.
- Validated extents [80,16384], controls [0,1000], palette sizes [1,4096], rush
  [0,1], and at most 1,000,000 ticks per FFI step bound invalid/extreme inputs.
  UI settings fall within these bounds. Intelligence still clamps to [0,1].
- Finite angle reduction uses modulo plus one adjustment instead of unbounded
  while loops, preserving +/-pi signs. Huge multi-revolution external angles
  can differ by f64 roundoff from repeated JS subtraction.
- Changing toroidal/deadly mode rebuilds trails to avoid mixing unwrapping
  conventions. Ordinary resize preserves the recorded curved path.
- Geometry changes are explicit, without QML's one-pixel debounce. Host code
  owns viewport/virtual-desktop selection and geometry notifications.
- Food IDs/counters use u64 and generation counters use u32. JS cannot exactly
  represent food IDs beyond 2^53; practical sessions never approach this.
- The JS growth budget is preserved, including its behavior that births and
  respawns can take total segments slightly above the world growth limit.
  Collision queries retain JS's adjacent-cell broad phase, including its
  limitations for artificially enormous teleports; normal speed bounds and
  the JS fast-head/narrow-seam scenarios are covered.
- Creation/reconfiguration can allocate and ultimately abort on host OOM,
  consistent with the specified abort profiles; successful steady ticks are
  allocation-free. Future Qt host integration/build plumbing is another stage.

No known in-scope game-mechanics behavior remains unported. Helpers/control,
presentation and persistence exclusions are identified above. No decisions or
external permissions are needed for this crate; review remains the orchestrator's.

Release build and tests pass without warnings. C smoke client compiles, links
and runs; the header also compiles as C++17 with `-Wall -Wextra -Werror`.
Clippy is not installed (`/usr/bin/cargo --list` has no clippy); skipped.
Mechanics coverage: body path replay, growth/interpolation insertion, vacuum
capture/continued lock/release, expiry/bounce/replenish, wraps and narrow-bin
seam hits, swept head/body checks and neck hits, all size differences around
